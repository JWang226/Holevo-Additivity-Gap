Reproducible verification

Check the formal proofs.

Run Lean, Comparator, or Nanoda separately, or run all three together. Works on macOS and Linux, following QMDL’s local verification approach.

Get the repository

Install Git, elan, Python 3.11+ with venv/pip, and native C/C++ build tools. Nanoda’s pinned-source build also needs Rustup. Dependency downloads need network access. Tool versions are pinned.

git clone https://github.com/JWang226/Holevo-Additivity-Gap.git
cd Holevo-Additivity-Gap

Run checks separately

Choose a command below. Each mode prepares its own dependencies and builds the proof modules it needs; no prior all run is required.

Lean

bash scripts/verify.sh lean

Rebuild all project sources, audit transitive axioms, validate mappings, and check six local expected types.

Comparator

bash scripts/verify.sh comparator

Use pinned Comparator APIs to compare expected types and referenced definitions, enforce the axiom policy, then replay exports in Lean’s kernel.

Nanoda

bash scripts/verify.sh nanoda

Build the pinned independent Rust kernel, run acceptance/rejection controls, and check the six exported solution theorem roots.

Lean and Comparator modes do not require Rust. Nanoda mode checks solution proofs; run Comparator as well to compare their expected statements.

Run all checks

bash scripts/verify.sh all

No landrun or systemd is required. Success ends with VERIFICATION PASSED: <mode>. Every requested stage must pass; a failure exits nonzero. Fresh logs and source-bound reports are written to .verify-work/run-*. The Lean stage also keeps detailed logs under .verify-work/logs/lean-*.

Trust and scope

Comparator and Nanoda run unsandboxed on trusted local sources. Comparator mode calls the pinned APIs directly; it does not claim a sandboxed upstream CLI run. Nanoda supplies an independent kernel implementation. Neither check replaces review of the expected statements, challenge imports, or their correspondence to the manuscript.

The six intentional expected-statement placeholders are excluded from the solution build. Solution proof dependencies permit only propext, Classical.choice, and Quot.sound. The principal endpoints are proved; the full manuscript is not formalized.
