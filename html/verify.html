Reproducible verification

Check the formal proofs.

Reproduce the Lean build and audit. For independent Comparator checking, use a separate fresh checkout so the proof sources are compiled under the prescribed sandbox.

1. Get the repository

On Linux or macOS, install elan, Git, Python 3.11 or later, and Python’s venv/pip support. Ensure elan is on your PATH. The repository pins Lean 4.29.0-rc6 and its Mathlib revision. Dependency downloads require network access.

git clone https://github.com/JWang226/Holevo-Additivity-Gap.git
cd Holevo-Additivity-Gap

2. Run the Lean verifier

The wrapper rebuilds the project sources, performs the complete transitive-axiom audit, validates metadata and every catalog declaration, and checks all six challenge types locally.

./verification/lean/run.sh

For usage and a prerequisite check:

./verification/lean/run.sh --help
./verification/lean/run.sh --check-prerequisites

Success prints LEAN REPRODUCTION PASSED. Comparator was not run. and returns exit code zero. The log directory is .verify-work/logs/lean-<UTC timestamp>-<process ID>/, with a status.txt record and per-step logs. Prerequisite checks download and build nothing; their success does not certify a proof.

3. Run Comparator separately

Execution status: the Comparator configurations and local statement checks are prepared and checked. End-to-end Comparator verification remains pending.

Use Linux with a nonprivileged account, Git, elan, Python 3.11 or later, a working systemd user session, and a real landrun installation. Comparator is pinned at a4f696825c583ed8a5b4060d9a0faa5b882d365b; the script preserves its committed manifest.

From the repository root used above, clone a fresh sibling checkout. Review the expected statements and their trusted imports before running the sandboxed verifier, and avoid compiling project proof sources outside that sandbox in this fresh checkout.

git clone https://github.com/JWang226/Holevo-Additivity-Gap.git ../Holevo-Additivity-Gap-comparator
cd ../Holevo-Additivity-Gap-comparator
./verification/comparator/run.sh --check-prerequisites
./verification/comparator/run.sh

The script builds the pinned Comparator and exporter, obtains trusted dependency cache material, and runs all five configurations for six expected statements. Each successful configuration must print Your solution is okay!; completion prints COMPARATOR REPRODUCTION PASSED: five configurations. Nanoda was not run. and returns exit code zero. Logs are retained in .verify-work/logs/comparator-<UTC timestamp>-<process ID>/. These configurations use Lean kernel replay; additional independent Nanoda checking is disabled.
